# Описание проекта

Компания использовала собственную биллинговую платформу **MC PAY**, в которой регистрировались пользователи.

До первой финансовой операции пользователь существовал только внутри MC PAY.

После первой финансовой операции необходимо было автоматически поставить его на финансовый учет в ERP-системе Microsoft Dynamics NAV (Navision), где создавался Vendor (контрагент).

До автоматизации процесс выполнялся вручную сотрудниками финансового отдела.

---

# Бизнес-задача

Построить надежную интеграцию между:

- PostgreSQL (MC PAY)
- n8n
- Microsoft Dynamics NAV (SOAP Web Services)

которая должна была:

- ежедневно находить новых финансовых пользователей;
- автоматически создавать Vendor в ERP;
- исключать дублирование;
- вести журнал выполнения;
- уведомлять финансовый отдел о результатах.

---

# Что было реализовано

## ETL-процесс

По расписанию (Cron, ежедневно в 09:00):

1. Выполнялся SQL-запрос к базе MC PAY.
2. Получался список новых финансовых пользователей.
3. Данные преобразовывались под требования ERP.
4. Выполнялась проверка существования Vendor по USER ID.
5. При отсутствии Vendor создавался через SOAP API.
6. Ответ XML автоматически преобразовывался в JSON.
7. Результаты записывались в журнал выполнения.
8. Финансовый отдел получал уведомление в Slack.

---

# Идемпотентность

Интеграция была реализована таким образом, чтобы повторный запуск процесса не создавал дубликаты.

Перед созданием Vendor выполнялась проверка:

```
Vendor No == USER ID ?
```

Если Vendor уже существовал —

создание пропускалось.

Это позволяло безопасно повторно запускать workflow после любых сбоев.

---

# Mapping

Для сопоставления пользователей MC PAY и ERP использовался файл соответствия:

```
USER ID  → Vendor No
```

Файл исторически являлся частью финансового процесса.

После создания нового Vendor соответствие автоматически дописывалось в mapping.

Данный файл далее использовался финансовым отделом для обработки транзакций.

# Работа с Microsoft Dynamics NAV

Интеграция выполнялась через SOAP Web Services.

Использовались операции:

- Read
- Create
- Update
- Delete
- ReadMultiple

Для взаимодействия использовались XML SOAP Envelope и авторизация через Web Service Authentication.

# Обработка ошибок

Основными сценариями ошибок являлись:

- недоступность ERP во время технических работ;
- отсутствие необходимых справочных данных (например Country Code);
- ошибки инфраструктуры.

При возникновении ошибки:

- информация записывалась в журнал;
- отправлялось уведомление в Slack;
- после восстановления ERP workflow безопасно запускался повторно с увеличенным диапазоном обработки данных.

---

# Производительность

На стороне Microsoft Dynamics NAV проблем с производительностью практически не возникало.

Основным ограничением оказался интерфейс n8n при отображении больших объемов данных.

При обработке выборок более 30 000 записей использовалась пакетная обработка.

Например:

```
1000 записей

↓

обработка

↓

следующие 1000

↓

...

↓

36000+
```

Это позволило избежать перегрузки интерфейса n8n.

---

# Тестирование

Перед публикацией все изменения проходили проверку в тестовой среде Microsoft Dynamics NAV.

Использовалась полноценная Sandbox-копия ERP.

Проверялись:

- создание Vendor;
- обновление;
- удаление;
- корректность SOAP-запросов;
- работа Cron;
- обработка ошибок.

После успешного тестирования для production менялись только учетные данные подключения.

# Инженерные выводы (Lessons Learned)

- SOAP остается эффективным инструментом для интеграции корпоративных ERP-систем и обеспечивает высокую производительность при работе с большими объемами данных.
- Основным узким местом интеграции может быть не ERP, а инструмент оркестрации или пользовательский интерфейс.
- Идемпотентность является обязательным свойством для любых ETL-процессов, работающих по расписанию.
- Полноценная тестовая среда значительно снижает риски при внедрении изменений в production.
- При работе с enterprise-системами важную роль играет взаимодействие с администраторами и поставщиками ERP (настройка доступов, публикация сервисов, изменение конфигурации).
